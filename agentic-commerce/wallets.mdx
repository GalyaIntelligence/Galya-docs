A **wallet** is one person's taste, kept by Galya and carried by their own AI agent across every store and
assistant. It is a workspace with one user, `self`, and the same API as any workspace: `/v1/item` (products the agent
found), `/v1/user` (omit `user_id`), `/v1/rerank`, `/v1/recommend` and `/v1/search`.

People get a wallet the first time they sign in to [Galya MCP](/agentic-commerce/mcp-server) with their own account.

## Sharing with a store

A wallet and a store's workspace stay separate. A store uses a person's wallet only after **the person agrees to
share with that store**:

<Steps>
  <Step title="The agent asks">
    "Can I share your taste with Acme?" Nothing happens until the person says yes.
  </Step>
  <Step title="The agent connects the store">
    After the yes, the agent calls `galya_connect_store` (`POST /v1/wallet/stores`).
  </Step>
  <Step title="Galya does the rest inside the platform">
    If the store runs Galya, Galya finds the person among the store's shoppers by their verified sign-in email. From
    then on the store's ranking for that shopper uses the wallet's taste instead of its own profile. If the store has
    not seen them yet, it connects the first time it does.
  </Step>
</Steps>

The store never receives the wallet itself, only the results of its usual calls. The person can stop sharing at any
time (`galya_disconnect_store`), and the store goes back to its own data about them at once.

<Note>
A store can never start this. Sending a shopper's `email` on its own changes nothing: the store's shopper is connected
only if that person already agreed to share with that store. Emails are stored only as a keyed hash, and responses
never say whether a wallet exists.
</Note>

If the store knows the person by a different email, or at a checkout, the agent can instead hand the store a one-off
**grant** (`galya_share_with_store`, `POST /v1/wallet/grants`), again only after the person agrees. The store passes
it as `grant` on `POST /v1/user`.

## For stores

Keep calling the API as usual, and pass the shopper's email when you have it:

```bash
curl https://api.galya.io/v1/user \
  -H "X-API-Key: $GALYA_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "user_id": "cust_123",
    "schema": "fashion",
    "email": "shopper@example.com",
    "rank": { "item_ids": ["sku_1", "sku_2", "sku_3"] }
  }'
```

`meta.profile` in the response says whose taste ranked the shopper: `workspace` (yours) or `wallet` (theirs, shared
with you).

## For wallets

A wallet calls these with its own credentials (a personal sign-in through Galya MCP, or a wallet key):

| Endpoint | Use |
|---|---|
| `GET /v1/wallet` | Email status and how many stores it shares with |
| `GET /v1/wallet/stores/search?q=` | Find a store running Galya by name |
| `POST /v1/wallet/stores` | Share with a store, after the person agrees (`workspace_id`) |
| `GET /v1/wallet/stores` | Stores it shares with: `connected`, or `waiting` for the store to see the person |
| `DELETE /v1/wallet/stores/{workspace_id}` | Stop sharing with a store |
| `POST /v1/wallet/grants` | A one-off grant for one store |
| `GET` · `PUT /v1/wallet/connector` | Where the person's connector acts by default |
| `DELETE /v1/wallet` | Erase the wallet and everything in it |

## Signals

Wallet history uses the same signals as any shopper, including the negatives people state in conversation:
`disliked` ("not for me", "hates", "never again") and `returned` ("refunded", "sent back").
