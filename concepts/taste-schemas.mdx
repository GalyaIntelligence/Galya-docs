## Readouts

The model is promptable: when you upsert an item, it looks at the item's image and text and answers every question in the [schema](/guides/schemas) you name. Each answer is a probability per option. Together they are the item's **readout**. A diver watch read through the [watches schema](/guides/schema-library#watches):

```json
{
  "q:watch_style": { "Diver": 0.91, "Sports": 0.07, "Field": 0.02 },
  "q:movement": { "Automatic": 0.84, "Quartz": 0.16 },
  "q:case_material": { "Steel": 0.88, "Titanium": 0.12 },
  "q:dial_color": { "Blue": 0.79, "Black": 0.21 }
}
```

The readout is the index. There is no separate indexing step and nothing to embed: once an item is `ready` for a schema, it can be ranked, filtered and searched through that schema.

- Questions you write show up as `q:<id>` fields. `galya-commerce-v3`, the fashion and apparel default, uses plain field ids such as `color` and `product_family`.
- One item can carry readouts for any number of schemas. Each is read once and reused until the item's `text` or `image_url` changes.
- You can [supply a readout yourself](/guides/items#bring-your-own-readout) and skip the model.

## Taste

A shopper's **taste** is Galya's prediction of what they will respond to, expressed in the same fields as the readouts. It comes from everything they have done — what they liked, saved, bought, lingered on and skipped — and it updates with every interaction.

Taste is read through whichever schema a call names, so one shopper's history works with any number of schemas, and you never re-record interactions when you add one.

## Ranking

Galya ranks items by how well they fit a shopper's taste, and keeps a page varied rather than filling it with variants of one product. Every ranked item carries `reasons`: the fields and options that made it a fit.

```json
{ "item_id": "watch_diver_42", "score": 0.42, "reasons": [
  { "field": "q:watch_style", "option": "Diver", "lift": 0.31 },
  { "field": "q:dial_color", "option": "Blue", "lift": 0.11 }
] }
```

A shopper with no interactions yet gets `score: 0` for every item, in the order you sent (or catalog order), so you can always render the result.
