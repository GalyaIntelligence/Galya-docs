Send a key on every call:

- Header: `X-API-Key: galya_sk_...`
- Or: `Authorization: Bearer galya_sk_...`

The playground in these docs asks for the same header. Paste a workspace secret; requests go to `https://api.galya.io`.

<Note>
  Keys are issued when Galya sets up your workspace. There is no self-serve sign-up. If you don't have a workspace yet, email [hello@galya.io](mailto:hello@galya.io) about a [pilot](https://www.galya.io/pilot/).
</Note>

## Keys

| Key | Prefix | Use it for | Where to find it |
| --- | --- | --- | --- |
| Workspace secret | `galya_sk_` | Server calls for one workspace | [API keys](https://app.galya.io/api-keys) |
| Workspace publishable | `galya_pk_` | Identifying the workspace in a browser. Not a secret. | [API keys](https://app.galya.io/api-keys) |
| Account | `galya_ak_` | Server calls across workspaces. Also send `X-Galya-Workspace-Id`. | [Settings](https://app.galya.io/settings) |
| Agent | `galya_ag_` | [Agentic search](/guides/agentic-search) only | Created with `POST /v1/agentic-search/keys` |

<Warning>
  A secret is shown in full once, in the browser session that created it. If you only see a prefix, create a new secret on [API keys](https://app.galya.io/api-keys). Never put a secret in a browser app; call Galya from your server.
</Warning>

## Workspace id header

A workspace secret is bound to one workspace, so omit `X-Galya-Workspace-Id`.

An account key is not. Send the workspace's public id with it:

```bash
curl "https://api.galya.io/v1/schemas" \
  -H "X-API-Key: $GALYA_ACCOUNT_KEY" \
  -H "X-Galya-Workspace-Id: wsp_..."
```

If the header does not match the key's workspace, the API returns `403` with `workspace_mismatch`.
