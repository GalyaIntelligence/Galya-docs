---
title: Search
description: "Search the catalog by intent with POST /v1/search: the items that match what the shopper asked for, in the order that fits their taste."
api: "POST /v1/search"
---

Search your catalog with what the shopper typed and get the matches in the order that fits them. This is the shortcut for [`POST /v1/user`](/guides/users#rank) with `rank.query`, without recording interactions.

The best matches for the query come first, and the shopper's taste orders them. Search never hides an exact match, even one Galya has not finished reading yet.

<ParamField body="query" type="string" required>
  What the shopper typed, up to 500 characters.
</ParamField>

<ParamField body="user_id" type="string">
  Order matches by this shopper's taste. Without it, matches keep their match-strength order.
</ParamField>

<ParamField body="schema" type="string | object" default="galya-commerce-v3">
  The [schema](/guides/schemas) to rank through.
</ParamField>

<ParamField body="where" type="string">
  Narrow the matches with the [`where` grammar](/guides/items#filter-the-catalog), e.g. `metadata.vendor = "Acme"`.
</ParamField>

<ParamField body="limit" type="integer" default="20">
  1 to 100.
</ParamField>

<ParamField body="include" type="string[]">
  `item` adds each result's title, image and metadata.
</ParamField>

<RequestExample>

```bash
curl https://api.galya.io/v1/search \
  -H "X-API-Key: $GALYA_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"query": "black boots for work", "user_id": "shopper_1", "limit": 12, "include": ["item"]}'
```

</RequestExample>

<ResponseExample>

```json 200
{
  "schema_id": "galya-commerce-v3",
  "ranked": [
    { "item_id": "sku_ankle_boot", "score": 0.31, "reasons": [{ "field": "color", "option": "Black", "lift": 0.22 }] }
  ],
  "meta": { "state_source": "cache", "latency_ms": 41 }
}
```

</ResponseExample>

To rank by taste alone, with no query, use [Recommend](/guides/recommend).
