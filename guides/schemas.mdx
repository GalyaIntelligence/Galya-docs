---
title: Schemas
description: "Galya schemas: the built-in galya-commerce-v3 fashion schema and your own natural-language questions, defined in code, content-addressed and unlimited per workspace."
api: "POST /v1/schemas"
---

A schema is the set of questions the model answers about each item. Every item and user call names one. Use the built-in schema, add your own questions on top of it, or use only your own.

## The built-in schema

`galya-commerce-v3` has 219 trained fashion fields: `color`, `product_family`, `silhouette`, `pattern`, `material`, `occasion`-style fields and more. It is the best-measured option, and the model's taste refinement covers its fields. Start here.

## Your own questions

A question has an `id`, the question `text` and 2 to 24 `options`. The model answers it per item as the field `q:<id>`.

```json
{
  "name": "occasion-and-fit",
  "base": "galya-commerce-v3",
  "questions": [
    { "id": "occasion", "text": "What occasion is this product for?", "options": ["Work", "Party", "Everyday"] },
    { "id": "fit", "text": "How does it fit?", "options": ["Slim", "Regular", "Relaxed"] }
  ]
}
```

- `base: "galya-commerce-v3"` includes the 219 built-in fields as well; `base: null` uses only your questions.
- Up to 64 questions per schema.
- Custom questions are answered zero-shot. Check a few readouts before relying on a new question.

<Tip>
  Keep schemas in your code and send the definition inline as `schema` on `/v1/item` and `/v1/user`. Galya stores it the first time and returns its id as `schema_id`. You never have to call this endpoint.
</Tip>

## Ids are content hashes

A schema's id is `sch_` plus a hash of its `base` and `questions` (`name` is only a label). So:

- The same definition always gets the same id, and posting it again returns `200` with that id.
- Schemas are immutable. Changing a question makes a new schema; the old one and its readouts stay usable.
- There is no limit on how many a workspace has.

<RequestExample>

```bash
curl https://api.galya.io/v1/schemas \
  -H "X-API-Key: $GALYA_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "occasion-and-fit",
    "base": "galya-commerce-v3",
    "questions": [
      { "id": "occasion", "text": "What occasion is this product for?", "options": ["Work", "Party", "Everyday"] }
    ]
  }'
```

</RequestExample>

## Manage schemas

- `GET /v1/schemas` lists the workspace's schemas and the built-in ones.
- `GET /v1/schemas/{schemaId}` returns one, with how many items have a readout for it.
- `DELETE /v1/schemas/{schemaId}` removes a schema you created.

## Taste across schemas

Interactions are stored once, without a schema. A user call computes taste through the schema it names, so one shopper's history can be read as fashion attributes in one call and as your `q:occasion` question in the next. If items don't have a readout for that schema yet, they are queued and listed under `not_ranked` with `pending`.
